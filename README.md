# Rollent 인사평가 웹앱 (프런트엔드 목업)

직원 등록부터 평가 진행, 점수 계산, 부서 KPI, 등급, 보고서 출력까지 한 흐름으로 동작하는 인사평가 웹앱 목업입니다.
**서버와 데이터베이스가 없는 프런트엔드 전용**이며, 모든 직원과 응답은 가상 데이터입니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ 에 정적 파일 생성 (Render Static Site: Publish Directory = dist)
```

## 로그인 (아이디 = 이름, 비밀번호 = 사번)

| 역할 | 이름 | 사번 |
|---|---|---|
| 관리자 (인사) | 관리자 | 0000 |
| 대표자 (최종 점수 직접 수정 권한) | 대표자 | 0001 |
| 사원 (생산팀) | 이서준 | 2019102 |
| 팀장 (생산팀) | 박성호 | 2015001 |
| 팀장 (관리팀) | 이수진 | 2015002 |
| 임원 | 장민석 / 강태호 / 송하은 / 윤지영 | 2008001 ~ 2008004 |

- 사번은 고유하므로 동명이인(생산팀·관리팀 `김민준`)도 이름+사번으로 각자 로그인됩니다.
- 전체 34명 목록: [public/samples/employees-34.csv](public/samples/employees-34.csv)

## 화면

| 사용자 | 메뉴 |
|---|---|
| 관리자 | 진행현황 · 직원 및 부서 관리 · 평가 관리 · 부서 KPI 관리 · 평가 결과 |
| 사원·팀장·임원 | 내 평가 (자기평가, 배정된 평가, 진행 상태) |

직원 및 부서 관리는 **임원 목록 · 부서 목록 · 직원 목록**으로 나뉘며 모두 같은 데이터를 봅니다.
- 임원 담당 배정은 임원 목록(담당 직원 배정·해제)과 직원 목록(담당 임원 열)에서 고칠 수 있고 서로 바로 반영됩니다. 한 직원은 임원 1명에게만 배정됩니다(복수 배정 정책 미설정). 테스트용 가상 배정과 관리자 지정 배정을 구분해 표시합니다.
- '활성 상태'(시스템 사용·로그인)와 '이번 회차 평가 대상'(평가 회차별 명단)은 따로 관리합니다. 비활성 직원은 대상이어도 평가에서 빠집니다.
- 직원 목록은 기본으로 팀장 → 사원 순이며, 열 제목을 눌러 오름차순·내림차순 정렬합니다.

평가 구조

| 평가 대상자 | 1차 | 2차 | 3차 |
|---|---|---|---|
| 사원 | 자기평가 | 팀장평가 (소속 팀장) | 임원평가 (배정된 임원, 필수) |
| 팀장 | 자기평가 | 팀원평가 (소속 팀원, 끌 수 있음) | 임원평가 (배정된 임원, 필수) |
| 임원 | 자기평가 (관리자가 켜고 끔) | - | - |

## 점수 계산 흐름

응답 → 항목 점수 → 단계 점수(100점 기준) → **개인평가 점수**(단계 가중치) → **백분위**(개인평가 점수 기준, 별도 값)
→ **KPI 반영** → **부서별·개인별 보정** → **최종 점수 직접 수정**(권한자) → **최종 점수** → A~D 등급 → 최종 확정 → 보고서

**배점 규칙:** 평가표(평가 단계)마다 그 단계에 쓰이는 점수 항목의 배점 합계가 정확히 100점이어야 평가 문항을 저장할 수 있습니다(화면과 저장 처리 모두 검사). 초기 테스트 데이터의 팀원평가표는 70점이라 조정이 필요합니다.

각 단계의 결과는 따로 저장되어 서로 덮어쓰지 않습니다. 보정값은 KPI 반영 후 점수에 더하는 점수(±)이며,
'미입력'과 '0'을 구분하고, '저장됨'과 '실제 적용됨'을 따로 표시합니다. 보정·직접 수정은 모두 변경 이력에 남습니다.

확정된 기준값: **사원 단계별 가중치 = 본인 20% · 팀장 40% · 본부장(임원) 40%**.
그 밖의 정책은 **정해지지 않아 '미설정'**이며, 미설정이면 그 정책이 필요한 단계만 계산을 보류합니다.
전체 상태는 **평가 관리 › 정책 설정 현황**에서 한눈에 볼 수 있습니다.

| 정책 | 설정 위치 |
|---|---|
| 팀장 단계별 가중치 (2차가 팀원평가라 확인 필요) | 평가 관리 › 가중치 및 계산 규칙 |
| 항목 안 여러 문항 → 항목 점수 | 평가 관리 › 가중치 및 계산 규칙 |
| 다수 평가자(팀원평가) 합산 | 평가 관리 › 가중치 및 계산 규칙 |
| 백분위 산출 공식·비교 집단·동점자 처리·비교 대상 제외 기준 | 평가 결과 |
| KPI 반영 공식·기준 점수·부서 KPI 점수 | 부서 KPI 관리 › KPI 반영 |
| 부서별·개인별 보정 적용 규칙 | 부서 KPI 관리 › 부서별/개인별 보정 |
| 조정·직접 수정 허용 범위, 승인 절차 | (후보 없음: 지금은 제한·승인 단계 없이 이력만 남김) |
| 등급 비율·인원 반올림·동점자 처리 | 평가 결과 |
| 결과 확정·재계산 규칙, 결과 공개 범위 | (후보 없음) |
| 임원별 담당 대상자 | 평가 관리 › 평가 단계 및 평가자 배정 (초기값은 테스트용 가상 배정) |

## 데이터 저장 범위

| 구분 | 내용 |
|---|---|
| 브라우저 localStorage | 직원, 부서, 문항, 배정, 응답, 설정, KPI, 조정 이력, 확정 결과. **같은 브라우저에서만** 유지되며 다른 기기·다른 사람과 공유되지 않습니다. |
| sessionStorage | 로그인 상태. 탭을 닫으면 로그아웃됩니다. |
| 초기화 | 진행현황 › '테스트 데이터로 되돌리기' |
| 업데이트 | 이전에 저장된 데이터는 지우지 않고 새 항목만 덧붙입니다. 이전 방식의 '개인 점수 조정' 기록은 계산에서 빼고 변경 이력으로 옮겨 보존합니다. |

변경 이력은 브라우저 안에 저장되므로 다른 기기와 공유되지 않고 개발자 도구로 바꿀 수 있습니다. 실제 감사 로그·위변조 방지에는 서버 저장이 필요합니다.

권한은 화면 이동(라우터)과 화면 안에서 확인하는 **목업 수준의 통제**입니다. 브라우저 개발자 도구로 데이터를 바꾸는 것까지 막지는 못하므로, 실제 서비스에는 서버 인증과 서버 측 권한 검증이 필요합니다.

## 보고서(PDF)

평가 결과 › '개인별 최종 보고서'(최종 확정된 직원만) 또는 '팀장 면담용 보고서' › 'PDF로 저장(인쇄)'을 누르고, 인쇄 창에서 대상(프린터)을 **PDF로 저장**으로 고릅니다.
여러 명을 고르면 PDF 하나에 사람별 페이지로 나뉩니다(개인별 파일 따로 받기·ZIP은 지원하지 않음).

## 폴더 구조

```
src/
  constants.js   평가 단계·역할·직급·정책 선택지
  seed.js        34명 가상 직원, 문항, 테스트 응답·배정
  store.js       데이터 저장, 로그인, 평가자 배정, 응답 저장, 진행 상태
  scoring.js     점수 계산 파이프라인 (개인평가·백분위·KPI·보정·직접 수정·등급을 단계별로 분리)
  policies.js    정책 목록과 설정 상태 (정책 설정 현황 화면)
  reports.js     보고서용 계산
  csv.js         CSV 읽기
  views/         화면 (관리자 5개 + 내 평가 + 평가 작성 + 로그인)
  components/    모달, 인라인 편집, 문항 설정, CSV 업로드, 보고서, 차트 등
public/samples/  CSV 샘플 (초기 34명, 신규·충돌·오류 예시)
tests/           브라우저 통합 테스트
```

## 통합 테스트

PC에 설치된 Microsoft Edge를 헤드리스로 띄워 필수 시나리오, 추가 시나리오 A~G, 2차 작업(백분위·KPI·보정·직접 수정) 시나리오를 실제 업무 순서대로 확인합니다(새 localStorage에서 시작).

```bash
npm run dev                 # 터미널 1
npm run test:smoke          # 터미널 2 (기본 주소 http://localhost:5173)
```
