# Rollent 인사평가 웹앱

직원 등록부터 평가 진행, 점수 계산, 부서 KPI, 등급, 보고서 출력까지 한 흐름으로 동작하는 인사평가 웹앱입니다.
**서버와 데이터베이스가 없는 프런트엔드 전용**이며, 모든 직원과 응답은 가상 데이터입니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/ 에 정적 파일 생성 (Render Static Site: Publish Directory = dist)
```

## 로그인 (아이디 = 이름, 비밀번호 = 사번)

| 역할 | 이름 | 사번 |
|---|---|---|
| 관리자 (인사 · 최종 점수 직접 수정 권한) | 관리자 | 0000 |
| 사원 (생산팀) | 이서준 | 2019102 |
| 팀장 (생산팀) | 박성호 | 2015001 |
| 팀장 (관리팀) | 이수진 | 2015002 |
| 임원 | 강태호 / 윤지영 | 2008002 / 2008004 |

- 사번은 고유하므로 동명이인(생산팀·관리팀 `김민준`)도 이름+사번으로 각자 로그인됩니다.
- 전체 32명 목록: [public/samples/employees-32.csv](public/samples/employees-32.csv)
- 로그인 화면 오른쪽 아래 🌐에서 한국어·English·Русский를 고르면 로그인 화면과 사원·팀장·임원 화면(평가 문항·선택지 포함)이 그 언어로 바뀝니다. 고른 언어는 이 브라우저에 기억되고, 관리자 화면은 한국어로 보입니다.
  - 번역은 [src/i18n.js](src/i18n.js)에 있습니다. 지금 등록된 문항과 샘플 CSV 문항, 부서·직급 이름이 들어 있고, 관리자가 새로 만든 문항처럼 번역이 없는 문구와 직원이 쓴 서술형 답변은 입력한 그대로 보입니다.

인사 CSV 열: `소속팀, 직급, 이름, 사번` · 문항 CSV 열: `평가항목, 항목배점, 적용단계, 문항, 답변유형, 필수, 선택지`
(적용단계는 `자기평가/팀장평가`처럼 /, 선택지는 `매우 그렇다=5;그렇다=4`처럼 ; 로 구분)
인사 CSV에는 담당 임원 열이 없으므로, 등록 후 '직원 및 부서 관리 › 임원 목록'에서 담당 직원을 배정해야 임원평가·상향평가가 생깁니다.

## 화면

| 사용자 | 메뉴 |
|---|---|
| 관리자 | 진행현황 · 직원 및 부서 관리 · 평가 관리 · 부서 KPI 관리 · 평가 결과 |
| 사원·팀장·임원 | 내 평가 (자기평가, 배정된 평가, 진행 상태) |

직원 및 부서 관리는 **임원 목록 · 부서 목록 · 직원 목록**으로 나뉘며 모두 같은 데이터를 봅니다.
- 임원 담당 배정은 임원 목록(담당 직원 배정·해제)과 직원 목록(담당 임원 열)에서 고칠 수 있고 서로 바로 반영됩니다. 담당 직원 배정 창에서는 **팀별 선택**(팀 단위로 한 번에)과 **개인별 선택** 중 고를 수 있습니다. 한 직원은 임원 1명에게만 배정됩니다(복수 배정 정책 미설정). 테스트용 가상 배정과 관리자 지정 배정을 구분해 표시합니다.
- '활성 상태'(시스템 사용·로그인)와 '이번 회차 평가 대상'(평가 회차별 명단)은 따로 관리합니다. 비활성 직원은 대상이어도 평가에서 빠집니다.
- 직원 목록은 기본으로 팀장 → 사원 순이며, 열 제목을 눌러 오름차순·내림차순 정렬합니다.

평가 구조

| 평가 대상자 | 1차 | 2차 | 3차 |
|---|---|---|---|
| 사원 | 자기평가 | 팀장평가 (소속 팀장) | 임원평가 (배정된 임원, 필수) |
| 팀장 | 자기평가 | 팀원평가 (소속 팀원, 끌 수 있음) | 임원평가 (배정된 임원, 필수) |
| 임원 | 자기평가 (관리자가 켜고 끔) | 상향평가 (담당 임원으로 배정된 팀장들) | - |

## 평가 회차

평가 관리 › 평가 문항 및 항목 위쪽에서 **평가 회차**를 고르고, **회차 복제**·**회차 삭제**를 할 수 있습니다.
- 고른 회차가 진행현황·평가 결과·부서 KPI·직원의 내 평가 등 모든 화면에 적용됩니다.
- 회차마다 문항·가중치·직급별 비율·계산 규칙과 평가 결과(응답·확정·보정·직접 수정·면담 기록·팀 KPI)가 따로 저장됩니다.
- 복제는 평가 정보(문항·가중치·직급별 비율·계산 규칙·평가 대상 명단·팀 KPI 지표와 목표)만 복사하고, 평가 결과와 팀 KPI 실적은 복사하지 않습니다.
- 직원·부서·임원 배정은 회차와 관계없이 공통입니다. 회차가 하나뿐이면 삭제할 수 없습니다.

## 점수 계산 흐름

응답 → 항목 점수 → 단계 점수(100점 기준) → **개인평가 점수**(1·2·3차 단계 가중치)
→ **부서 KPI 반영**(개인평가·팀 KPI를 직급별 비율로) → **개인별 보정** → **최종 점수 직접 수정**(관리자) → **최종 점수** → A~D 등급 → 최종 확정 → 보고서

- **팀 KPI** (부서 KPI 관리 › 팀별 KPI): 지표마다 목표·실적·가중치를 넣으면 달성률(높을수록 좋음 = 실적÷목표, 낮을수록 좋음 = 목표÷실적)을 구하고,
  환산점수(달성률, 최대 100) × 가중치의 합이 팀 KPI 점수입니다. 지표 대신 점수를 직접 입력할 수도 있습니다.
  테스트 데이터에는 가상 지표가 3개씩 들어 있습니다(생산팀 93.4 · 관리팀 92.7 · 경영진 93.0). CSV로 새로 등록한 부서는 KPI를 직접 넣어야 합니다.
- **단계 가중치** (평가 관리 › 가중치 및 계산 규칙): 처음 값은 사원 본인 20·팀장 40·임원 40, 팀장 본인 20·팀원(상향) 40·임원 40, 임원 본인 20·상향 80입니다.
  꺼진 단계(팀원평가, 임원 자기평가)는 계산에서 빠지며 켜진 단계의 합계가 100%여야 합니다.
- **직급별 비율** (부서 KPI 관리 › 직급별 비율): 개인평가 점수에 팀 KPI 실적을 반영하는 비율입니다. 처음 값은 사원 80/20, 팀장 60/40, 임원 40/60(개인평가/팀 KPI)입니다.
- 백분위는 계산하지 않습니다.

**배점 규칙:** 평가표(평가 단계)마다 그 단계에 쓰이는 점수 항목의 배점 합계가 정확히 100점이어야 평가 문항을 저장할 수 있습니다(화면과 저장 처리 모두 검사). 초기 테스트 데이터의 팀원평가표는 70점이라 조정이 필요합니다.

각 단계의 결과는 따로 저장되어 서로 덮어쓰지 않습니다. 부서별 보정은 없고 **개인별 보정**만 있습니다. 보정값은 부서 KPI 반영 후 점수에 더하는 점수(±)로, 저장하면 바로 반영되며 '미입력'과 '0'을 구분합니다.

확정된 기준값: **사원 단계별 가중치 = 본인 20% · 팀장 40% · 본부장(임원) 40%** (팀장·임원도 같은 비율로 처음 값을 넣음).
그 밖의 정책은 **정해지지 않아 '미설정'**이며, 미설정이면 그 정책이 필요한 단계만 계산을 보류합니다.
전체 상태는 **평가 관리 › 정책 설정**에서 한눈에 볼 수 있습니다.

| 정책 | 설정 위치 |
|---|---|
| 사원·팀장·임원 단계별 가중치 | 평가 관리 › 가중치 및 계산 규칙 |
| 항목 안 여러 문항 → 항목 점수 | 평가 관리 › 가중치 및 계산 규칙 |
| 다수 평가자(팀원평가) 합산 | 평가 관리 › 가중치 및 계산 규칙 |
| 팀 KPI·직급별 비율 | 부서 KPI 관리 › 팀별 KPI / 직급별 비율 |
| 조정·직접 수정 허용 범위, 승인 절차 | (후보 없음: 지금은 제한·승인 단계 없음) |
| 등급 방식(상대평가: 비율·인원 반올림·동점자 / 절대평가: A·B·C 기준 점수) | 평가 결과 |
| 결과 확정·재계산 규칙, 결과 공개 범위 | (후보 없음) |
| 임원별 담당 대상자 | 평가 관리 › 평가 단계 및 평가자 배정 (초기값은 테스트용 가상 배정) |

## 데이터 저장 범위

| 구분 | 내용 |
|---|---|
| 브라우저 localStorage | 직원, 부서, 문항, 배정, 응답, 설정, KPI, 조정 이력, 확정 결과. **같은 브라우저에서만** 유지되며 다른 기기·다른 사람과 공유되지 않습니다. |
| sessionStorage | 로그인 상태. 탭을 닫으면 로그아웃됩니다. |
| 초기화 | 진행현황 › '테스트 데이터로 되돌리기' (처음 가상 데이터로) |
| 전체 삭제 | 진행현황 › '전체 삭제' (직원·부서·평가·문항·팀 KPI 중 골라서 비움, '전체 삭제' 입력 필요) |
| 업데이트 | 이전에 저장된 데이터는 지우지 않고 새 항목만 덧붙입니다. 이전 방식의 부서 KPI 점수는 팀별 KPI의 '직접 입력' 점수로 옮깁니다. |

권한은 화면 이동(라우터)과 화면 안에서 확인하는 **프런트엔드 수준의 통제**입니다. 브라우저 개발자 도구로 데이터를 바꾸는 것까지 막지는 못하므로, 실제 서비스에는 서버 인증과 서버 측 권한 검증이 필요합니다.

## 보고서(PDF)

평가 결과 › '개인별 최종 보고서'(최종 확정된 직원만) 또는 '팀장 면담용 보고서' › 'PDF로 저장(인쇄)'을 누르고, 인쇄 창에서 대상(프린터)을 **PDF로 저장**으로 고릅니다.
여러 명을 고르면 PDF 하나에 사람별 페이지로 나뉩니다(개인별 파일 따로 받기·ZIP은 지원하지 않음).

## 폴더 구조

```
src/
  constants.js   평가 단계·역할·직급·정책 선택지
  seed.js        32명 가상 직원, 문항, 테스트 응답·배정
  store.js       데이터 저장, 로그인, 평가자 배정, 응답 저장, 진행 상태
  scoring.js     점수 계산 파이프라인 (개인평가·팀 KPI·직급별 비율·보정·직접 수정·등급을 단계별로 분리)
  policies.js    정책 목록과 설정 상태 (정책 설정 화면)
  reports.js     보고서용 계산
  csv.js         CSV 읽기
  views/         화면 (관리자 5개 + 내 평가 + 평가 작성 + 로그인)
  components/    모달, 인라인 편집, 문항 설정, CSV 업로드, 보고서, 차트 등
public/samples/  CSV 샘플 (초기 32명, 신규·충돌·오류 예시, 새 조직 인사 데이터, 평가 문항)
tests/           브라우저 통합 테스트
```

## 통합 테스트

PC에 설치된 Microsoft Edge를 헤드리스로 띄워 필수 시나리오, 추가 시나리오 A~G, 2차 작업(부서 KPI·보정·직접 수정) 시나리오를 실제 업무 순서대로 확인합니다(새 localStorage에서 시작).

```bash
npm run dev                 # 터미널 1
npm run test:smoke          # 터미널 2 (기본 주소 http://localhost:5173)
```
